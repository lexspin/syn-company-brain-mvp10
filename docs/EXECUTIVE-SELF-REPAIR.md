## Recovery and review evidence

For a stale queued request, compare its immutable bindings to current records/files. Retain the stale request as failed with the exact reason. Let the existing outbox coalesce current sources; do not execute old instructions or create a competing owner. A running request belongs to its claimant and must be reconciled.

Check normal routing, missing tools, changed sources, duplicate occurrences, conflicting ownership, uncertain receipts, bounded retry and rollback. Match any completion claim to an observed artifact or result. Unit fixtures validate mechanics; a live command receipt validates only that command. Scheduled end-to-end execution requires an observed eligible occurrence.

Capture useful evidence once and reuse it across reviews. System repair owns reproduced integration defects, prompt review owns procedure transfer, interface review owns human flow and the executive combines their findings. Retain original failures, source versions and counterexamples. Link the completed result to its project, selected skills and affected loops; verify exact-ID retrieval, bounded search and MAPS publication.
