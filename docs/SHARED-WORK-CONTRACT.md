# Shared agent and workflow contract

For every task: identify the owner outcome and current project direction; resolve the external product root and the OS root; retrieve the smallest relevant current evidence; select exact skills and available tool schemas; define acceptance before dispatch. Route routine work to the requested Sol profile and bounded thinking to Astra medium where the actual execution surface supports it. Configuration labels are not executed calls.

One accountable owner coordinates each outcome. Each worker handoff names writable paths, inputs/source versions, output destination, dependency, acceptance tests and return evidence. Check active ownership before editing; parallel workers use disjoint scopes. Don't load every skill or send all memory to every worker. Resolve contradictions against current owner instructions and project scope; preserve distinct domain voices.

Return useful results and explicit failures, not merely a completion label. Verify the actual tool result, saved output and relevant user-facing flow. Unavailable connectors, simulated tests and unreviewed media stay visibly unverified. Record source versions and before/after evidence. Save useful bounded memory, update reciprocal links and MAPS through the queue, and retain rollback history. Product artifacts stay outside this OS repository.

Prompt review researches and benchmarks methods; system repair verifies implementation and legacy compatibility; interface audit checks human utility; dreaming proposes future directions; document upkeep archives only verified supersession. Each consumes preceding review evidence, avoids overlapping fixes, and leaves unresolved work with a clear next owner/action. Candidate ideas do not become accepted plans automatically.
# Failure and correction memory

Owner direction, 10 October 2026: retain useful failures, fixes, prompt revisions and pass/fail evidence so later work can avoid repeating known mistakes. Before repeating or changing a workflow, retrieve relevant lessons for its exact skill, loop and project. A failed attempt remains evidence even after a successful replacement.

At the outcome boundary, archive a concise lesson through the live queue: observed failure and affected versions; reproduction or run receipt; cause (confirmed or suspected); actual change; before/after result; regression check; unresolved limits; rollback/predecessor link. Link the affected project, skills, workflow and source records and verify publication. Preserve original instructions and failed-run receipts; do not copy private raw logs or credentials into Knowledge.

Apply explicit reusable owner corrections within their scope. Inferred fixes to reasoning remain candidate procedures until tested. No issue is marked prevented merely because a prompt was rewritten. Future reviews check the retained regression case; a recurrence updates the lesson instead of creating contradictory duplicates. This reduces repeat failures without promising that an agent will never make a mistake.
